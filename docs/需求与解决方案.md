# 需求与解决方案

## 1. 产品背景与目标

产品定位为运行在端侧 AI 主机上的视觉创作工作台。图像与视频内容创作者可在画布上生成、编辑和组合图像，完成完整创作任务。产品由设备、本地模型和创作应用协作；**目标方案要求所有模型推理在本地完成，不设置云端推理兜底**。

当前产品聚焦静态电商素材。核心问题不是“再做一个聊天式生图工具”，而是把商品素材处理、背景构思、版式编辑和多尺寸交付放进同一条可理解、可调整的画布工作流。

## 2. 用户与场景选择

### 目标用户

图像及视频类内容创作者中的电商运营、中小商家、个人品牌创作者和设计外包人员。他们需要做商品视觉素材，但不一定熟悉专业图像软件。

### 主要痛点

- 商品图、抠图、背景制作、文字排版和尺寸适配往往散落在不同工具中。
- 快速生成的图不一定能直接上架；商品外观、文字与构图需要人工确认和调整。
- 商品图片与未发布素材可能较敏感，不适合默认上传云端处理。

### 为什么选电商素材

电商成品以静态图片为主，输入和交付边界清晰；主体抠图、背景、促销文案及图层组合都适合用画布表达；同一商品需要多尺寸、多版本，能体现创作工作台的价值。单张图片任务有明确的输入、输出和验收边界，适合在端侧主机上分批运行并按队列管理。相较短视频生成，它不需要处理长时序和跨帧一致性，更适合作为本地模型方案与交互原型的验证场景。

电商素材是当前选择的切入场景，后续可根据使用反馈扩展到其他视觉创作场景。

## 3. MVP 模块及协作

以下模块构成首个可用版本的核心范围；账号体系、模型市场、局部重绘和专业修图等扩展能力不纳入当前范围。

| MVP 模块 | 解决的问题 | 与其他模块的协作 |
|---|---|---|
| 项目与画布 | 给每次创作一个可返回的工作空间 | 项目承载素材、图层、任务和导出 |
| 素材导入与主体分离 | 把商品原图变成可组合的主体素材 | 原图和抠图结果进入素材库，由用户选择置入画布 |
| 本地生成与结果预览（目标能力） | 为商品提供场景背景或创意候选 | 生成结果先作为候选素材，用户确认后才置入画布 |
| 图层编辑与组合 | 处理商品位置、大小、文字、装饰及层级 | 用户对素材、背景和文字分别调整；保存记录画布状态 |
| 保存、恢复与导出 | 避免正常刷新丢稿，并输出可使用的成品 | 画布快照可恢复；导出读取当前可见图层并生成多尺寸文件 |

**扩展能力（不作为 MVP 必需）：** 单设备任务队列、进度与取消、失败重试、生成期间编辑和中断恢复。它让耗时推理不冻结画布；结果仍由用户确认后置入。详见[任务调度方案](./任务调度方案.md)。

**目标产品协作关系：** 项目/画布组织创作，素材模块准备输入，本地推理模块产出候选，图层编辑完成组合，保存与导出交付结果。任务队列属于后续增强；设备能力、模型状态和本地任务调度提供运行保障。当前原型不实现商业账号或云部署。

## 4. 目标工作流

1. 新建项目或打开示例画布。
2. 导入商品照片；系统校验文件后放入素材库。
3. 在本机运行抠图，查看透明背景结果；不满意时保留原图并允许重新处理。
4. 选择商品主体置入画布，摆放商品位置与尺寸。
5. 输入背景描述并提交本地生成任务；任务在后台排队，画布仍可编辑。
6. 在结果区预览候选；用户选择后再置入画布，不自动替换原有图层。
7. 增加或调整标题、促销角标、说明文字及图层顺序。
8. 保存画布；刷新后恢复项目。
9. 选择目标规格导出 PNG/JPEG，检查成品后下载。

其中第 5 步的**目标产品实现必须是本地推理**。当前原型的该步调用云端百炼，是与产品目标不一致的实现差距。

## 5. 目标模型与运行方案（设计建议，未部署）

| 环节 | 建议方案 | 选择理由与边界 |
|---|---|---|
| 本地背景生成 | SDXL 1.0 base，FP16；通过 Diffusers + PyTorch 执行 | 作为电商场景背景候选的本地生成基线，生态和管线易于串入应用。ControlNet 可作为后续结构控制实验，不是首版必需项。 |
| 商品抠图 | 以本地 U2Net 作为小型原型基线；目标方案可对比 BiRefNet | 当前 U2Net 已真实运行过；BiRefNet 是候选升级项，是否值得替换应由同一批商品图的边缘质量与速度评估决定。 |
| 精度/量化 | 首轮以 FP16 为主，不默认启用 INT8/8bit | 先保住商品材质、边缘和细节质量；低精度方案只有在目标硬件实测收益且质量退化可接受后才采用。 |
| 执行设备 | Apple Silicon 使用 PyTorch MPS；NVIDIA 使用 CUDA | 由本机推理引擎完成计算。运行失败应明确报错，不转发至云端。 |
| 硬件假设 | 设计评估基线：NVIDIA 独显约 24GB 显存；现有开发设备为 Apple M5、24GB 统一内存 | 这是测试规划假设，不是已验证的 SDXL 兼容性或性能结论。不同设备需分别实测。 |

不在本轮下载或部署大型生成模型。当前原型只有 U2Net 在本机运行；SDXL、BiRefNet、ControlNet 以及 FP16/量化生成性能均未在本项目验证。

### 质量与速度取舍

**取舍：优先质量，不为追求更短等待时间而默认降低生成质量。** 电商图是可交付素材，商品外观失真或边缘错误会使图片不可用。等待体验通过任务排队、进度反馈、生成期间继续编辑改善，而不是通过云端兜底或未经验证的量化换速度。

## 6. 目标方案、原型事实与差距

| 范围 | 目标产品方案 | 当前原型实际情况 |
|---|---|---|
| 推理位置 | 所有生成与抠图均在本机；无云端兜底 | U2Net 抠图在本机；文生图连接百炼云端，与目标不一致 |
| 工作空间 | 画布承载素材、生成候选和编辑图层 | 项目、画布、素材、文字/形状图层、保存恢复和导出已实现 |
| 背景生成 | 本地模型生成候选，由用户确认置入 | 生成面板接入云端文生图；本轮未发起调用 |
| 任务管理 | 单设备本地队列、失败可见、草稿可恢复 | 有后台队列和状态持久化；本地/云端取消语义有区分；三项真实生成并发流程未验证 |
| 模型状态 | 展示设备与本地模型可用性 | 设置页同时说明当前演示模型与未部署的本地目标模型 |
| 商业化能力 | 不属于当前产品原型范围 | 不建设商业账号、计费或云部署体系 |

**范围说明：** 当前交付聚焦核心交互原型，不代表完整目标产品已经实现。当前云端生成是原型偏差，不应表述为目标产品支持云端推理；更完整的专业编辑和产品化能力也不在当前范围内。
